## A. AI MODELS — what shipped (12–19 August 2026)

### 🔴 CLAUDE TEXT IS NOW WATERMARKED — everywhere, including the API and Claude Code

This is the most operationally consequential finding of the week for Adrian specifically, because every venture's copy passes through this engine.

- **Anthropic published the mechanism on 14 August.** The watermark is **SynthID-Text**, the technique Google DeepMind published in a peer-reviewed 2024 *Nature* paper. Instead of using an arbitrary random source to choose between equally valid next words, the model uses a key plus the preceding words to settle the choice — **leaving a pattern across many low-stakes word choices that a reader cannot perceive but a key-holder can detect.** [CONFIRMED first-party — [Anthropic, *How Claude's text watermarking works*](https://www.anthropic.com/news/claude-text-watermark)]
- **🔴 The scope is total, and this is the part that matters: marking applies "everywhere you use Claude, including Claude Platform (API), Claude, Claude Code, Claude Cowork, and Claude Tag"** — worldwide, and across AWS, Google Cloud and Microsoft Foundry. [CONFIRMED first-party — [Anthropic support: How Claude marks AI-generated content](https://support.claude.com/en/articles/16266773-how-claude-marks-ai-generated-content)]
- **It is not only text. Signed C2PA provenance metadata is attached to supported file types — `.svg`, `.png`, `.jpg`.** [CONFIRMED first-party — same support article]
- **Timing: models launched on or after 2 August 2026 support marking at launch; models older than that are being back-filled "over coming months."** [CONFIRMED first-party]
- **Only Anthropic holds the key.** A **watermark detection API is promised "soon"** but is not shipped and implementation details are unfinalised. **There is no third-party detector today.** [CONFIRMED first-party]
- **Removal: light editing will not remove it. "A complete rewrite where every word is replaced" will.** [CONFIRMED first-party]
- **Stated limitations, and they are the useful half: detection works poorly on short passages, thins out on factual text (where accuracy constrains the model to one right answer and leaves the watermark nothing to act on), and is minimal in code.** [CONFIRMED first-party]
- **Anthropic's own caveat, quoted because it is the honest one: "a detected mark provides a signal that content was processed by Claude, but is not fully conclusive"** — it cannot distinguish *Claude wrote this* from *Claude edited this*, and it carries **no user, organisation or conversation information whatsoever.** [CONFIRMED first-party]
- **Framing: this is an EU AI Act Code of Practice on Transparency commitment**, i.e. a compliance obligation, not a product feature — which is why there is no documented opt-out. **⚠️ Whether an API customer can disable it is NOT addressed in either first-party document. I checked both and it is absent — recorded as unanswered, not as "no".** [CONFIRMED absence]
- **The rollout was announced 11 August and detailed 14 August, with a further Anthropic clarification round on 15 August.** [CONFIRMED secondary — [TechCrunch 11 Aug](https://techcrunch.com/2026/08/11/anthropic-says-it-will-watermark-text-generated-by-its-ai-models/), [TechCrunch 15 Aug](https://techcrunch.com/2026/08/15/anthropic-shares-more-details-about-how-claudes-new-watermarks-will-work/), [Forbes](https://www.forbes.com/sites/anishasircar/2026/08/13/claude-will-now-leave-a-watermark-on-everything-it-writes-what-does-that-mean/)]

### 🟢 The best method piece of the week: an overnight auto-research loop on codex that got a 232× kernel speedup

  1. **`/goal` with a specific quantitative target** let it run autonomously overnight. We use `/goal`; we rarely give it a *number* to beat.
  2. **`/btw` for non-blocking oversight** — course-correct without interrupting the loop. **This is the missing primitive in our overnight grinds**, where checking on a run generally means interrupting it.
  3. **🔑 Beam-search discipline: maintain 3–5 candidate idea families rather than forcing every experiment to beat the current best.** The author names this as what stopped premature convergence to a local maximum. **Our council-ask fans out for *triangulation on one question*; this is fanning out to *hold several hypotheses alive across time*, which we do not currently do.**
  4. **Structured logging of every attempt** to prevent re-exploring dead ends.
- **The honest limit, and it is the sort of detail that makes the rest credible: the bottleneck was launch and panel overhead, not compute — "we were rarely memory or compute bound."** The loop's value was in finding *that*, not in raw grinding. [CONFIRMED]

### 🟢 Anthropic's own guidance on getting more out of Claude Code — first-party, specific, and it contradicts habits we have

Published 14 August, 318 pts on HN. **This is the highest-value operational item in the digest after the watermark.** [CONFIRMED first-party — [Anthropic, *Maximizing the value of your Claude Code sessions*](https://claude.com/blog/maximizing-the-value-of-your-claude-code-sessions)]

- **Set `/model` and `/effort` at session start — changing either mid-conversation busts the prompt cache** and forces re-prefilling the entire history. (Our delegation-doctrine §14.3 already says this; **now first-party confirmed.**)
- **`/clear` between tasks**, so prior work stops being re-sent every turn.
- **Run `/context` in a fresh session** to see what is auto-loaded — tool definitions, CLAUDE.md, MCP servers — and remove what is not needed. **For this vault, with a very large loaded instruction layer and many MCP servers, that is not a small number.**
- **@-mention files instead of typing paths** — attaches the file directly, avoids a separate Read call, keeps the cache intact.
- **🔑 `/rewind` instead of `/compact` when discarding recent turns** — rewinding keeps earlier cached content intact at zero cost, while compacting rewrites the whole conversation. **We reach for `/compact` by reflex.**
- **`/compact` BEFORE stepping away**, because the prompt cache expires after one hour (five minutes on API keys) — summarising while still cached is far cheaper than resuming cold.
- **`MAX_THINKING_TOKENS=0` for routine grunt work** — goes below even `/effort low`. Not on Fable 5.
- **Add quiet flags to noisy commands or run them in subagents** — command output persists in the conversation like a file and accumulates across every remaining turn. **Store the flagged form in CLAUDE.md.**
- **Subagents for high-output jobs (log analysis, repeated noisy tasks)** where context cleanup matters more than re-reading cost.

> 🔧 **THE COLLECTOR BUG — FOUND, FIXED, TESTED THIS RUN.** `tools/model-intel-harvest.sh` had **two compounding defects**, and the second was invisible behind the first.
> **(1) Recency truncation** — it used Algolia `search_by_date` and then sliced `[:25]`, i.e. *"the 25 most RECENT matches, then the top 8 by points."* Any high-scoring story more than a day or two old fell out of the sample before the points filter ever saw it. This was diagnosed on 13–14 August and left open.
> **(2) The real killer, found only after fixing (1): multi-word AND-matching.** Algolia ANDs full-text terms, so the query `"LLM GPT Claude Gemini Grok model"` required **all six words in one story** and matched **nothing** — verified directly: `nbHits: 0` across the whole 7-day window. The 12 August fix correctly killed a literal `" OR "` but replaced it with a space-joined string that was just as broken, and the missing date filter masked it by dragging in stale all-time matches.
> **The fix:** a real server-side `created_at_i` window filter over the requested N days, a 200-hit page, terms **pipe-separated and queried separately then merged and deduped**, and the whole window ranked by points — no recency truncation. Explicit failure reporting when a sub-query returns unparseable output, so a silent zero can never again read as "quiet week."
> **Measured on the identical window: 1 usable story → the real top 8, topping out at 967 points**, surfacing the watermark backlash (810), Anthropic's Claude Code guidance (318), the codex auto-research piece (455), the Copilot/Snowflake compromise (416) and the Sol price cut (611) — **every one of which this digest would otherwise have missed.** Backup: `tools/model-intel-harvest.sh.bak-20260819-recency`. Verified by re-running and reading the output. **The "quiet week in community signal" conclusion in the runs of 13 and 14 August was an artefact of this bug and should not be trusted.**
> **(3) The precision problem the fix created, also closed in this run rather than parked.** Broad pipe-separated terms are *necessary* (Algolia ANDs multi-word queries) but they made every bucket over-inclusive: the first repaired run returned an IKEA product-naming article and a management-consultancy essay under *"Marketing / ads / funnel tactics"*, and Count Binface's by-election result under *"AI coding / agents"*. **`hn()` now takes an optional fourth argument — a relevance regex matched against title+URL — applied to all three buckets.** After the gate all three are clean, and it surfaced two more genuinely relevant stories the noise had been crowding out (GPT-5.6 Sol's vision result at 359, an Anthropic multi-model degradation incident at 145). **Verified by re-running and reading all three buckets.**
>
> **🔴 (4) AND THE REASON THERE IS NO DIGEST FOR 15–18 AUGUST — found in the run log, and it is not a research problem.** `tools/model-intel-run.sh` ran correctly every one of those mornings and collection succeeded each time. **The headless `claude -p` synthesis step died on `Failed to authenticate: OAuth session expired and could not be refreshed`** — the known headless-keychain failure mode (`memory/claude-code-headless-keychain-login.md`). **It then wrote a single `WARN` line into a log nobody reads and exited quietly, four mornings running.** That is the whole defect: **a standing automation that can fail silently is a standing automation nobody is actually running**, and the gap was only noticed by a human on the 19th.
> **Fixed:** the failure branch now files `working/handoffs/<date>-claude-URGENT-model-intel-harvest-failed.md`, which the SessionStart hook lists to *every* new session, and it **diagnoses the cause rather than leaving the reader to dig** — it distinguishes an auth failure from a usage-limit failure by reading the log tail and states the specific fix and the manual re-run command. **Tested by driving the failure branch with a simulated expired-OAuth log; the alert rendered with the correct auth diagnosis.** Deliberately **not** a push notification: AGENTS.md §7 sends vault status, alerts and errors to handoffs and dashboards, never into Adrian's personal apps. Backup: `tools/model-intel-run.sh.bak-20260819-silentfail`.
