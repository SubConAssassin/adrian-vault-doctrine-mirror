### 🔴 OpenAI slowed Astra over "Critical" cyber capabilities — the genuine new story this window

- **On 7 August OpenAI said it "cannot rule out" that Astra meets its internal "Critical" threat tier for cyber capability**, and has responded by **expanding safety testing and pausing internal activities that do not meet stricter security requirements.** Preliminary evaluations showed strong **agentic coding** capability, which is what drove the designation. [CONFIRMED — [Axios exclusive](https://www.axios.com/2026/08/07/openai-astra-model-delay-cybersecurity-risks) (403s to WebFetch, read via search summary + corroborating outlets), [Benzinga](https://www.benzinga.com/markets/private-markets/26/08/61057336/openai-slows-astra-model-release-after-cybersecurity-warnings), [Stocktwits](https://stocktwits.com/news-articles/markets/equity/open-ai-to-slow-down-astra-model-release/cZofOvtRJ9m)]
- **What "Critical" means in OpenAI's own framework:** the ability to **autonomously identify and exploit zero-day vulnerabilities, or execute complex attacks against highly secure targets, without human intervention.** [CONFIRMED as the published definition — same sources]
- **The careful reading, which most coverage skips: Astra has NOT been formally declared Critical.** OpenAI has not published the evaluations that would establish the threshold; it has said it cannot *rule it out*. It is partnering with government bodies and independent safety institutes for evaluation before broader deployment. [CONFIRMED — [techjournal](https://techjournal.org/openai-pauses-astra-critical-cyber-risk); the distinction is stated in the reporting itself]
- **Status unchanged otherwise: Astra has no date, no pricing, no model card, no ChatGPT availability**, and OpenAI has still not said whether it ships as GPT-6, a GPT-5 point release, or under the Astra name. Announced 1 August inside a blog post about ten machine-checkable maths/TCS proofs. **Flagship remains GPT-5.6 (Sol / Terra / Luna).** [CONFIRMED — carries from the 08-09 run; [Gizmodo](https://gizmodo.com/openai-smuggled-the-announcement-of-astra-its-next-ai-model-into-a-blog-post-about-math-2000793689)]

> **Why this matters to us beyond curiosity:** the slowed item is specifically **agentic coding capability**, which is the exact capability class our whole delegation architecture is built on. It is the first public evidence that the frontier's next step up in agentic coding is being gated on security rather than capability. No action; it is a directional read on how fast the ceiling moves next.

## B. INNOVATIVE USES — what people are actually doing

**This week's community signal is about restraint, not capability** — specifically, bounding agents so they stop.

- **`maxTurns` is now named as mandatory practice for bounded subagents, not an optimisation.** The stated failure mode: subagents "get expensive when they keep exploring, testing, and re-checking without a clear stopping point." **Set `maxTurns` on every subagent with a bounded job.** [CONFIRMED as community guidance — [UX Planet subagent optimisation](https://uxplanet.org/best-practices-for-claude-code-subagents-optimization-7ff0dd3e20b5), [Claude Code sub-agents docs](https://code.claude.com/docs/en/sub-agents)] **⚠️ INFERRED as best practice, not vendor-measured.**
- **The parallelism sweet spot is now given as 3–5 concurrent subagents, with "beyond 10 rarely provides additional benefit and increases costs significantly."** [CONFIRMED as community consensus — same sources] **Worth holding against our own numbers:** §11.3's hard cap is 10–12 *CLI clients* on the M1 Max, and §5's guidance allows 16× subagent fan-out. These measure different things — CLI processes vs Claude subagents — but the community number is meaningfully below our fan-out ceiling, and it is a *value* claim (diminishing returns), not a *capacity* claim.
- **The named test for whether a subagent should exist at all:** repeated often · describable as a separate role · likely to produce context noise · better with restricted tools · better on a cheaper/faster model · useful across projects. "**The biggest mistake is treating subagents like a collection of tools for every possible activity.**" [CONFIRMED as guidance — [UX Planet](https://uxplanet.org/best-practices-for-claude-code-subagents-optimization-7ff0dd3e20b5)] This is §1b.3's tier-pinning law arrived at independently by the community.
- **The hub-and-spoke framing, stated more sharply than we state it ourselves:** the coordinator "does no domain work itself — no research, no analysis, no generation. **This separation is what makes the coordinator reusable across different task types.**" [CONFIRMED as a described pattern — [claude-code-ultimate-guide](https://github.com/FlorianBruniaux/claude-code-ultimate-guide/blob/main/guide/workflows/agent-teams.md)] That is the CEO doctrine's §1 in one sentence, and it is a better sentence than ours.
- **Two discipline rules worth stealing verbatim:** "**Demand evidence — 'show me the test output,' never 'it works.'**" and "**clear the session after two failed corrections; compact around 50%.**" [CONFIRMED as guidance — [dev.to workflow practices](https://dev.to/galian/claude-code-workflow-best-practices-that-ship-code-na)]
- **Skills vs hooks vs subagents has settled into a clean three-way split**: Skills = long-lived expertise loaded when relevant · Hooks = deterministic shell side-effects at lifecycle events · Subagents = forked instances with their own context window. **"Pair an MCP connection with a skill that teaches Claude how to use it"** is named as materially better than either alone. [CONFIRMED directionally — [Totalum](https://www.totalum.app/blog/claude-code-skills-totalum)]
- **Local-model community signal (r/LocalLLaMA, aggregated):** the recommended evaluation toolkit is **LMSYS Arena + the LiveBench/Aider-Polyglot/SWE-Bench-Verified triad + r/LocalLLaMA + your own 20-prompt eval** — the last item being the one that actually decides it. For 24GB GPUs, **Qwen 3.6 32B and DeepSeek V4 Flash** are the current all-rounders. [CONFIRMED directionally — [StationX best local LLM, August 2026](https://app.stationx.net/articles/best-local-llm), [KDnuggets](https://www.kdnuggets.com/top-7-coding-models-you-can-run-locally-in-2026)] **Directly relevant to the M2 Studio monthly local-eval cadence: the "your own 20-prompt eval" is the part we already have infrastructure for and the part the aggregators say matters most.**
