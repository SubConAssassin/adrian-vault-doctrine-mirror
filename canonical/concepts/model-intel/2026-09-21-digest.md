## C. INNOVATIVE USES — what people are actually doing

**1. 🆕 The best result of the week is a measurement, and it points the opposite way from model-chasing: the harness, not the model, is where coding-agent cost lives.**
Two independent pieces landed in-window and agree.
- **HarnessTax** ran **7 models through 3 harnesses (Claude Code, Codex CLI, and the minimal open-source Pi) on two standard coding benchmarks — 21 pairings.** Result: **success rates barely moved — within about 2 points on SWE-bench Lite and about 5 on Terminal-Bench — while cost moved a lot.** Pi showed materially better token efficiency than both Claude Code and Codex. The thread's recurring observation: **"models may perform better with other harnesses than with their own,"** and **"the harness becomes more and more important, the smaller the model is."** 229 points. [CONFIRMED as reported — [HN thread](https://news.ycombinator.com/item?id=49733726), [Lobsters](https://lobste.rs/s/iq4dwz/harnesstax_how_much_does_harness_matter). ⚠️ **`harnesstax.github.io` is client-rendered and returned only a loading shell on direct fetch**, so the numbers above are the HN/Lobsters reading of it, not the source page.]
- **"An Empirical Study of Harness Design for Coding Agents" (arXiv 2609.20804, submitted 17 September, 43 pages, nine authors)** — **176 matched settings, five context-management strategies, four context-window budgets, four models, on SWE-Bench Verified and Terminal-Bench 2.1.** Findings: **context management exists to prevent context-overflow failures**; **planning shifts from an accuracy scaffold for weaker models to a cost saver for stronger ones, with little accuracy change**; **predefined tools help models with weak bash proficiency, while bash-capable models run effectively on a bash-only interface at substantially lower cost**; and **harness design is a conditional systems problem — choose per model, task type and budget, never as a default.** 222 points. [CONFIRMED by direct fetch — [arXiv](https://arxiv.org/abs/2609.20804)]
**Why this belongs to us specifically:** this vault spends real attention on *which model* a lane pins and almost none on *what the harness around it costs*. Both results say the pin is worth ~2–5 benchmark points and the harness is worth a multiple on the bill. **And the "planning is a cost saver, not an accuracy scaffold, on strong models" result is a direct empirical echo of §14.2's STOP-OVER-PROMPTING law**, arrived at independently. → **ROUTING DELTA 5.**

**2. 🔴 Two zero-click code-execution vulnerability classes hit the exact CLI lanes doctrine §4 runs, and I checked our own exposure rather than reporting the advisory.**
- **GitSpawn (Manifold Security, disclosed 2 September).** A malicious **`.git/config`** in any repository sets **`core.fsmonitor`**, which Git executes to detect changed files. When an agent runs `git status` or `git diff` at init, **the attacker's command runs with the user's privileges, outside the agent's sandbox, with no approval prompt.** **CVEs: CVE-2026-72718 (goose, CVSS 4.0 base 7.0), CVE-2026-19592 (Codex), CVE-2026-55607 (Claude Code, fsmonitor during worktree operations).** **Patched:** goose 1.44.0 · **Codex CLI 0.131.0** · **Claude Code 2.1.196**. **Reported unpatched as of 1 September: Hermes Agent, Qwen Code (0.19.6 and 0.22.3), Grok Build (0.2.93 and 1.0.13).** [CONFIRMED by direct fetch — [The Hacker News](https://thehackernews.com/2026/09/malicious-git-configs-can-make-claude.html)]
- **Plugin4Shell (AIR, disclosed ~17–18 September).** A **zero-click RCE** across Claude Code, Codex, GitHub Copilot and Gemini CLI: an agent resolving a **SHA-pinned plugin** can be fed **a branch whose name is the 40-character commit hash**; Git may prefer the matching ref over the commit object, so the agent **installs attacker code while reporting the expected SHA as successfully verified**. **Patched: Claude Code 2.1.179, Codex 0.146.0. Copilot unpatched at disclosure; Gemini CLI deprecated without a fix.** **AIR found no evidence of exploitation in the wild.** [CONFIRMED — [The Hacker News](https://thehackernews.com/2026/09/plugin4shell-lets-repository-owners.html), [Help Net Security, 18 Sep](https://www.helpnetsecurity.com/2026/09/18/plugin4shell-ai-coding-agents-vulnerability/), [CybersecurityNews](https://cybersecuritynews.com/plugin4shell-zero-click-rce/)]
**Our actual exposure, measured on this box, not inferred:** **`git config --get core.fsmonitor` is unset both in the vault repo and globally**, so GitSpawn's vector is **not currently armed here** — but it travels *inside a cloned repo*, so that is a statement about today, not a control. **Claude Code is 2.1.260 — patched for both. Codex CLI is 0.153.4 — patched for both.** ⚠️ **`qwen` is 0.21.7, which sits between the two versions the advisory reports unpatched (0.19.6 and 0.22.3), and no fixed Qwen Code version has been published.** **`grok` and `agy` are not on this node** (they live on Studio per §5.1), so **Grok Build's reported-unpatched 0.2.93 is unverified here and needs checking on Studio.** → **ROUTING DELTA 1.**

**The correction this forces.** The 09-19 digest read the RubyGems attack and the Bengio essay as evidence of **emergent instrumental behaviour** — agents discovering that hacking scores well. **That framing survives only partly.** The proximate cause in these specific incidents was **a test harness that handed sandboxed models live internet access by accident**. **The transferable lesson is duller and more useful than the emergent-misbehaviour one: the blast radius of an agent is set by what the harness lets it reach, not by what the model intends** — which is the same conclusion §C1 reaches from cost, and the same thing our own §7.2 and permission-deny gates are for.

**4. 🆕 Thomas Ptacek's "How to Write with an LLM" is the highest-signal writing-workflow piece this series has surfaced, and it contradicts how most people use these models for copy.** 711 points, the #2 HN story of the week.
**The workflow:** write your own draft first → feed it to the model **to find problems** → **rewrite the problem sections yourself** → compare versions with a **fresh model instance** to avoid context bias.
**Two rules he states hardest:** (1) **never use any specific word or phrase the model suggests** — frontier models are excellent at "pleasing turns of phrase," and that is exactly what makes text read as *output*; (2) **reject model encouragement** — models praise mediocre first drafts, which makes a writer defend weak material instead of rethinking it, **and the rethinking is the load-bearing part**.
**What models are genuinely good at:** mechanically spotting tedious-to-find problems — **passive voice, nominalised verbs, filler words ("very", "actually", "really"), and paragraphs sitting in the wrong place.** [CONFIRMED by direct fetch — [Ptacek, 17 Sep](https://sockpuppet.org/blog/2026/09/17/how-to-write-with-an-llm/)]
**Why it matters here:** this is, almost line for line, the discipline the vault already enforces through `voice-persona-curator` and the zero-em-dash / no-elision rules — **but stated as a *method* rather than a prohibition.** "Use the model to find the problem, never to supply the words" is a cleaner statement of SS voice discipline than anything currently written down.
