## C. NOT MODELS — the two items with the most operational consequence for us

### 🔴 A published RCE chain against Claude Code auto mode, which Anthropic has declined to patch

This is the finding I would put in front of Adrian first, because this stack runs Claude Code unattended, overnight, in bypass-permissions mode, on the box that holds `~/.config/com.adrian-vault/.env`.

- **The attack, from Johann Rehberger (embracethered), published ~1 September.** A malicious site serves a ZIP. Claude falls back from WebFetch to bash/curl when the site returns HTTP 415. Claude extracts the archive. It *refuses* to run the attacker's supplied binary decoder — correctly — and then **writes its own decoder using stdlib modules and runs it from inside the extracted directory**, at which point an attacker-controlled `struct.py` shadows the standard-library module on import and executes arbitrary code. **The refusal is load-bearing to the exploit: the safety decision is what creates the vulnerable path.** [CONFIRMED — [embracethered](https://embracethered.com/blog/posts/2026/breaking-claude-code-opus-5-and-automode/)]
- **Measured 60–80% success across variants.** Demonstrated payloads included C2 callbacks, file writes, and spawning nested Claude instances. [CONFIRMED]
- **🔴 Anthropic classified the report "Informative" and shipped no patch,** stating: *"Auto Mode is a convenience feature backed by a best-effort classifier, not a security guarantee."* Their position is that **OS isolation and network egress control are the actual security boundary** — not the approval classifier. [CONFIRMED — quoted in the writeup]
- **The mitigations Anthropic names are: containerise the agent, restrict network egress, monitor agent activity, and do not expose sensitive credentials to agents.** [CONFIRMED]
- **Our exposure, stated plainly and not softened: none of those four are in place on M1.** Sessions run unsandboxed with bypass permissions, with full network egress, on a box holding live API keys for every venture. **This is a real found fault under `AGENTS.md` §14 and I am parking it under §14.4 rather than acting on it — reason (a) is a genuine architecture call plus an existing safety-gate design, owner is Adrian, trigger is this morning's read.** Re-plumbing the fleet's sandboxing unattended overnight would be the more dangerous act. It is named in the alert file.

## D. INNOVATIVE USES — what practitioners are actually doing

- **Cache-aware agent architecture is now an explicit cost strategy, not a micro-optimisation.** With Fable 5.1 cache reads at $0.25/M and Muse Spark's at $0.15/M (88% off), the winning shape is a **stable cached prefix — system prompt plus codebase plus standing rules — re-read across a long session**. Practitioners report ~50% cost cuts on Cursor-Bench-style loops. **The inverse is the trap: churn the prefix, or run single-turn heavy reasoning, and 1.7× output tokens makes you worse off than before.** [CONFIRMED secondary — latent.space]
- **Teams are repositioning Fable 5.1 as a planner/router rather than the executor**, precisely because its output-token appetite is expensive but its planning is the best measured. Cheap models do the fanned-out execution. [CONFIRMED secondary — latent.space]
- **Image-to-3D pipelines are the standout demo workflow of the week**: property photos → generated house designs → Blender renderings → cinematic walkthrough. **Directly transferable to AGA Bali's site visualisation and to OSB product renders — and it runs through Blender, which this stack already drives.** [CONFIRMED secondary as a reported workflow; the transferability is INFERRED — my read]
- **🟢 Small but genuinely useful to Adrian: lexical analysis of Fable 5.1 output shows measurably fewer hyphenated compounds and fewer em dashes than Fable 5.** The em-dash ban is a standing HARDEST rule in this vault enforced by post-hoc repair. This does not retire the rule — it means the raw output should need less repair. [CONFIRMED secondary — latent.space]
- **The context-engineering consensus hardened this week into a usable formula.** The framing everyone converged on: **most agent failures are context failures, not model failures.** The recommended artefact before any first code-generation prompt is a short engineering contract stating **goal, non-goals, constraints, affected files, acceptance criteria, and test expectations**. [CONFIRMED secondary, multi-source — [Martin Fowler / Thoughtworks](https://martinfowler.com/articles/exploring-gen-ai/context-engineering-coding-agents.html), [Addy Osmani](https://addyosmani.com/blog/ai-coding-workflow/), [LogRocket on AGENTS.md + skills](https://blog.logrocket.com/context-engineering-for-ides-agents-md-agent-skills/)]
  - **Note for us: that is close to what `tools/ag_preflight.py`'s mandatory commission frontmatter already enforces** (objective, output_path, output_min_words, validation_tests, expected_artifacts). The delegation doctrine's §6 prescriptive-prompt law is the same idea. **No change needed — recording that the outside world arrived where our doctrine already is.** [INFERRED — my read]
- **The loudest complaint is not about capability, it is about who captured the efficiency gain.** API customers got the 75% cache cut; **claude.ai and Claude Code subscribers report unchanged usage caps despite the 20–37% efficiency improvements**, alongside rate limits, broken continuation, and safeguard false positives on theoretical mathematics and metaphorical language. [CONFIRMED secondary — latent.space]
- **One dissenting practitioner data point worth keeping**, because it cuts against the benchmark story: a developer working in Rust and Lean reports **Fable 5 outperforming Fable 5.1 at both**. Benchmark leadership is not uniform across languages. [CONFIRMED as a reported opinion — latent.space]
