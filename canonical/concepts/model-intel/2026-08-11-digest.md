## B. INNOVATIVE USES — what people are actually doing

**This week's community signal is routing and context economics** — how to spend less on the same work, and where the agent's attention actually goes.

- **🔴 The week's top AI story on Hacker News is a model router, and it is worth reading against our own routing engine.** [**Weave Router**](https://github.com/workweave/router) (216 pts) is a drop-in proxy that picks the model **per action rather than per conversation turn**, using *"a tiny on-box embedder"* and a cluster scorer derived from Avengers-Pro, deciding in **under 50ms**. - **Distilling DeepSeek into GPT-OSS does not transfer censorship** (170 pts) — [ctgt.ai research](https://www.ctgt.ai/research/distillation-censorship-transfer). Relevant as a general fact about what survives distillation, not as anything we act on.
- **"Context engineering" has displaced "prompt engineering" as the named discipline, and the framing is genuinely useful: write · select · compress · isolate.** *Write* = keep context outside the active window (scratchpads, memory files, running plans) so the model does not re-derive what it established two steps ago. *Select* = filter to what is relevant. *Compress* = summarise and condense. *Isolate* = split across separate context windows so one task's noise never contaminates another's. **The stated premise is the sharp bit: agent failures are primarily context failures, not model failures.** [CONFIRMED directionally — [Sourcegraph](https://sourcegraph.com/blog/context-engineering), [Atlan](https://atlan.com/know/ai-agent/context-engineering/context-engineering-techniques-ai-agents/), [mem0](https://mem0.ai/blog/context-engineering-ai-agents-guide)]
  - **This vault already does all four, under different names** — the event log and ledgers are *write*, the boot read-order is *select*, the STATE-OF-STACK rotation is *compress*, and worktree-isolated subagents are *isolate*. **The value is the vocabulary, not the technique**: it gives a clean way to name which one a given change is improving. §14.8's outstanding compression work is a *compress* problem, and the MCP context-overhead finding is a *select* problem.
- **The surface-selection guidance has settled and now reads cleanly**: *Hooks* enforce rules · *Skills* carry contextual knowledge · *Subagents* provide delegation boundaries with their own context window · *`CLAUDE.md`* is always-on project guidance. Stated rule of thumb: **reach for a subagent first, move to a skill when you want the same instructions inline.** [CONFIRMED as community guidance — [Totalum](https://www.totalum.app/blog/claude-code-skills-totalum), [Tembo](https://www.tembo.io/blog/claude-code-subagents), [SmartScope](https://smartscope.blog/en/generative-ai/claude/claude-code-best-practices-advanced-2026/)]
- **Two practices named repeatedly enough to adopt outright**: cap `max_turns` on every bounded subagent (second consecutive run), and **prefer `Explore` agents over `general-purpose` for search**, because Explore is optimised for fast codebase navigation and returns conclusions rather than file dumps. [CONFIRMED as guidance]
- **Local agentic coding is now described as viable for daily engineering work**, with the honest caveat repeated in the same sources: **for genuinely hard agentic coding the closed frontier is still ahead on SWE-Bench Verified by a meaningful margin.** The recommended decision procedure is unchanged and remains the one that matters — **your own 20-prompt eval**.
