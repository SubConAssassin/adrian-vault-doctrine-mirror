> ### 🔴 FOUR BREAKING API CHANGES — the operationally load-bearing part of this week
> These return **HTTP 400**, they are not deprecation warnings. [CONFIRMED — [digitalapplied breaking-changes analysis](https://www.digitalapplied.com/blog/claude-opus-5-5-launch-pricing-benchmarks-2026); consistent with first-party "thinking mode cannot be disabled"]
> 1. **Thinking cannot be disabled.** `thinking: {"type":"disabled"}` or a manual `budget_tokens` → 400. Omit thinking, or send `{"type":"adaptive"}`, and control depth with `effort`.
> 2. **Forced tool use removed.** `tool_choice` set to `"any"` or to a specific tool → 400. Use `auto` with `strict: true`, or structured outputs.
> 3. **Thinking blocks are bound to context.** Replaying a thinking block after the system prompt, tools or an earlier message changed → 400. Conversations must be append-only; change instructions via mid-conversation system messages, not edits.
> 4. **Old computer-use tool rejected.** `computer_20251124` → 400 on the Claude API and Vertex (Bedrock still accepts it). Migrate to `computer_toolset_20260801`.
>
> **Plus one SILENT failure, which is the dangerous one:** model-generated notes between tool calls now return as `thinking` blocks rather than `text` blocks. With the default `display: "omitted"` they render **empty, with no error**. Anything streaming progress updates between tool calls goes blank and reports success. Fix: set an explicit `thinking.display`.

## C. INNOVATIVE USES — what's actually working in the wild

### The harness, not the model, is where this week's real evidence is

- **"An empirical study of harness design for coding agents"** — **176 experimental configurations** across SWE-Bench Verified and Terminal-Bench 2.1, four models, fixed execution loop with targeted component ablations. Four findings worth reading as doctrine rather than news: [CONFIRMED — [arXiv 2609.20804](https://arxiv.org/abs/2609.20804)]
  1. **"Context management becomes increasingly valuable as the context-window budget tightens, with most of its benefit coming from preventing context-overflow failures."**
  2. **"Staging rule-based elision before LLM-based summarization provides the strongest overall efficiency"** — cheap deterministic pruning *first*, model summarisation *second*.
  3. **"Planning shifts from an accuracy scaffold for weaker models to a cost saver for stronger models, with little change in accuracy."** On a frontier model, a planning step buys you money, not correctness.
  4. **"Predefined tools improve performance for models with weaker bash proficiency, whereas bash-capable models can operate effectively with a bash-only interface and achieve substantially lower cost."**
- **HarnessTax** (230 pts HN) asks the same question. ⚠️ **`harnesstax.github.io` is client-rendered and returned a loading shell to WebFetch — same failure as 09-21.** Not sourced; the arXiv paper above covers the ground with citable numbers.

### Claude Code subagent practice has converged on a recognisable shape

- The community rule of thumb that keeps recurring: **reach for subagents when a task touches 10+ files, or has 3+ independent pieces of work** — and specifically when a side task would flood the main context with logs or search results you will never reference again. Concrete pattern in circulation: **three parallel reviewers with different lenses** (security → auth/injection, performance → N+1/caching, tests → coverage gaps). Two hard rules: **only independent units** (two subagents writing one file will race), and **partition before fanning out**. Per-subagent tool scoping — researcher gets read-only + web, writer gets Edit/Bash but no network — so one bad subagent cannot poison the rest. [CONFIRMED as practice — [Anthropic](https://claude.com/blog/subagents-in-claude-code), [Tembo](https://www.tembo.io/blog/claude-code-subagents)]

### The MCP backlash became a front-page argument

- **"MCP was always a bad idea?"** (330 pts HN). The criticisms are specific, not vibes: **context bloat** (multiple servers' tool schemas crowd the window, forcing generic search/execute workarounds); **obsolescence** (models can now run code, read `--help`, and call APIs directly, so the intermediary earns less); **redundancy** ("most remote-service MCP servers ultimately wrap APIs that already exist"). Proposed alternative: direct HTTP/CLI with **content negotiation** — `Accept: text/markdown` so servers return agent-friendly text rather than verbose JSON/HTML — citing Cloudflare's Code Mode and Vercel/Shopify engineers. [CONFIRMED as argument — [maharship](https://maharship.com/blog/why-mcp-was-always-a-bad-idea/)]
- **Why it matters here rather than as discourse:** this session alone loaded several hundred MCP tool schemas. The context-bloat criticism is the one with a measurable local cost.

### Meta — the creative-testing playbook has actually changed, and the old split is dead

- **The pre-2026 testing formula no longer holds.** Meta is different under the hood: **Andromeda at retrieval, GEM in the auction, and Entity ID instead of per-file uniqueness.** With Advantage+ and simplified structures, the algorithm decides impression split between creatives *inside one ad set*, based on which Entity IDs actually hook users. **The old "70% budget on proven, 30% on tests" split "falls apart in 2026."** [CONFIRMED-ish, practitioner-sourced — [Affect Group](https://affectgroup.com/blog/how-to-test-creatives-in-meta-ads-in-2026-a-working-system-in-the-era-of-advantage-and-andromeda/)]

- **Creative elements currently working:** **social proof (reviews/ratings) in the first 3 seconds** to stop the scroll; mobile-first, **85% watch without sound** so text overlays and vertical format are non-negotiable. **Andromeda scales winners aggressively, which causes fatigue faster** — monitor frequency and refresh on declining CTR / rising CPM. [CONFIRMED-ish]
- **Meta's own headline number:** Advantage+ Sales users saw **+32% ROAS and −17% CPA** vs manual-only, with **8M+ advertisers** on its AI creative tools. [CONFIRMED as a **vendor claim** — [AdsUploader](https://adsuploader.com/blog/meta-ads-updates), [AdMove](https://www.admove.ai/blog/meta-advantage-creative-best-practices-for-2026).
